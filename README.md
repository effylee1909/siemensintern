# 週會紀錄工作台

本機處理的繁體中文網頁，以「上傳 PPT → 整理雙語議程與摘錄重點 → 會議中補充討論」為主要流程，Word 匯入為輔助。示範會議次數為第 219、220 次，下一次自動延續為第 221 次；討論內容只有虛構範例；實際附件與會議內容未納入原始碼。

## 啟動

Node.js 22 或 24（本環境驗證 24.19.0）。

```sh
cd /workspace/siemensintern
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

伺服器只綁定本機介面，不直接對外開放。瀏覽器於同一部電腦開啟本機 5173 連接埠。雲端環境若沒有瀏覽器轉送功能，可將程式放到公司核准的電腦執行；不要為此直接公開公司資料。`npm run build` 產生 `dist/`，可由公司核准的靜態伺服器提供。未部署到公開網站。

## 使用流程

1. 網站預設開啟空白工作區，不自動載入 3 筆示範議題。可直接上傳 PPT；需要時按「觀看示範」試用。使用「清除工作區」可重新建立第一場會議，指定最早一場會議日期、會議次數與名稱（可從第 219 次開始）。之後可用標題下方的「編輯會議名稱、次數與日期」修改。
2. 上傳本次 `.pptx`，系統開啟「整理成會議紀錄」預覽：確認雙語議題、重點、負責人及來源頁碼，勾選本次要討論的議題。可見頁的所有候選議題（含關閉項目）預設選取；隱藏頁、附錄預設不選，可使用全選或逐項勾選；圖表／非標準版型須人工確認。可依封面採用會議次數與日期，或連結前次／本次的既有議題。確認後自動產生紀錄，會議中只需補充討論與決議。也可以用「新增議題」直接編寫。若已有 Word 紀錄，可選擇輔助匯入 `.docx`。支援 Topic / Description / Note / PiC（舊版沒有 PiC 也可），跳過空白列。無議題名稱的非空白列保留並提示補填；不要假定此列與前列是同一議題。
3. 匯入預覽確認跨週連結。相同名稱僅提供建議，不同名稱可手動連結。每場會議同一議題只能有一列，避免覆蓋既有紀錄。
4. 開會前建立下次會議，預設帶入所有未關閉議題（包括狀態留白的項目）並清空本次描述與備註。已關閉議題只留在歷史。若要匯入已完成的下一場 Word 紀錄，取消「帶入未關閉議題」，再匯入並連結前次議題。「建立下次會議」日期需晚於最新會議；補錄以前的會議請用「新增歷史／其他會議」，可輸入任意日期，列表自動排序。
5. 編輯本次紀錄，左側對照最近一次有紀錄的會議（不一定是前一週），「完整歷程」查看全部。
6. 每場會議的「本次會議簡報」可上傳多份 `.pptx`，保留原檔下載與議題來源原文；切換會議時只顯示該場附件。不重建圖表、圖片、版面，也不自動推定簡報議題與 Word 議題的關係。簡報原檔與文字參考會放入一般備份，不會帶入下一場會議。
7. 編輯後自動儲存到目前瀏覽器，右上角顯示「已儲存在此瀏覽器」後可關閉或重新整理。下次同一瀏覽器開啟會自動載入。定期「下載備份」產生包含全部會議的備份：有 PPT 原檔時為 ZIP，沒有原檔時為 JSON；換電腦／瀏覽器時用「開啟備份」，無須密碼。Word 匯出使用中英文並存的五欄表格，內容欄分成雙語簡報重點與雙語會議討論，但不保留原始範本的頁首、Logo 或完整版面。

## 資料保護與限制

- 檔案解析在瀏覽器執行，不呼叫外部 AI、追蹤、CDN、外部字型或 API。依賴打包到網站，非執行時遠端載入。
- 紀錄使用 IndexedDB 自動存檔，含會議、議題與保留的簡報資料，不加密、不傳送到 GitHub。正在儲存或儲存失敗時會提示；儲存失敗仍可下載一般備份。無痕模式、清除網站資料、儲存空間不足或換裝置可能失去本機資料，因此仍應下載備份。
- 一般備份為 `.zip`（含原檔）或 `.json`（沒有原檔），可直接讀取、不需密碼。所有欄位均未加密，能使用同一瀏覽器或取得備份的人也能讀取內容。舊 `.meeting` 加密備份仍可用原密碼匯入，之後改用未加密本機儲存與 ZIP／JSON 備份；不再提供產生加密備份的介面。
- Word 匯出未加密，應依公司分類、存取權限及保存政策處理。清除工作區會取代本機資料，但不會刪除下載檔案、原始文件或此雲端對話的附件。使用者已上傳此對話的附件並不因本機網頁模式而變成只存在公司電腦。
- 上傳支援 .docx / .pptx，不支援舊 .doc / .ppt；單檔 100 MB；每場最多 20 份簡報，取消原檔合計 40 MB 的固定上限，總量依瀏覽器配額與磁碟可用空間而定。JSON／舊加密備份開啟上限 100 MB，完整 ZIP 備份上限 20 GB；解壓縮 XML 大小亦有限制。不要處理不可信來源的 Office 文件。
- 正式多人上線前需公司資訊安全核准、公司 SSO / RBAC、HTTPS、伺服器驗證與存取控制、操作稽核、加密儲存、備份與保留政策。此版本沒有多人協作、登入、伺服器資料庫或權限控管，不是可直接公開的企業系統。
- 建議在公司管理裝置、核准瀏覽器與私有網路使用；部署時設定 HTTP CSP（含 `frame-ancestors 'none'`）、HSTS、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、敏感入口 `Cache-Control: no-store`。HTML CSP 僅提供基礎防護，不能取代伺服器安全措施。

保留儲存庫 `effylee1909/siemensintern`，網站路徑命名為 `siemens_weekilymeeting`（依指定拼字）。預定網址為 `https://effylee1909.github.io/siemensintern/siemens_weekilymeeting/`。

## PPT 自動整理與雙語內容

- 依實際簡報頁序解析文字與表格，讀取隱藏頁、階段／分類、項次、狀態與負責人。以議題表格列為候選議題，非標準頁面標記人工確認；不執行文件中的指令、巨集、外部關聯或連結。
- 中英文分開保存；依原文句子擷取最多三個重點，優先選取待辦、要求、目前進度與近期更新。這是啟發式**摘錄式摘要**，不是語意生成摘要或翻譯服務，兩種語言的重點也不保證逐句對應。句子取捨可能漏掉重要條件，應核對完整原文與原始簡報。
- 每個議題的中英文名稱、重點、討論、備註、負責人、分類皆可分別編輯。原文缺少語言時留白並提示補充；英文會議討論不會由中文自動翻譯。來源未提供的負責人、分類、狀態等欄位保持空字串，不推定為「進行中」或任意分類。Word 匯出缺少內容也保持空白，不填「未提供」或範例文字。請在分享前補齊需要的英文。
- 相鄰的中英文頁有相同項次／分類且語言互補時，可合併；不同項次或僅標題／縮寫相似的議題不會自動合併；非標準頁也各別保留供核對。來源頁碼保留。表格辨識、語言判別及合併皆可能需要校正，預覽中可改標題、重點、負責人及議題連結；若合併不符本意，可用手動新增及原文補正。
- 更新本次既有議題時，保留已寫好的雙語討論、備註、狀態及非空負責人，避免重建紀錄覆寫會議內容。反覆整理同一附件可更新摘要，不增加同一連結議題。建立下一場時清空上次的摘要與來源，保留議題身份與雙語名稱；再用新 PPT 更新本次重點。
- 舊版備份仍可開啟；舊附件首次整理會從原檔重新解析。PPT 原文、表格資料、原檔、雙語紀錄都納入一般備份，不會上傳 GitHub。
- 圖片、掃描頁、SmartArt、圖表資料、動畫內容與講者備註沒有 OCR／完整還原，不能宣稱已涵蓋其重點；請人工確認。若將來要加自動翻譯或更深入的語意摘要，應使用公司核准的本機模型或受控服務，先確認資料處理政策，不直接傳送會議資料到公開 AI。

預覽中的「已選／候選」即為即將整理的項目數，需按「確認建立紀錄」才會套用到會議。每議題最多摘錄三個重點，並不是最多三個議題。若重新開啟舊備份，既有紀錄與示範內容會原樣保留，不會為了修正預設畫面自動刪除。

## 補錄歷史會議與歷次簡報

- 左側「新增歷史／其他會議」可在第 219 次之後補第 218、217 次或其他次數，不會帶入其他會議的討論內容。按日期排序（相同日期再按次數），同一次數不重複建立。會議日期也可改到較早或較晚日期，對照依重新排序後的時間順序運作。
- 「批次上傳歷次 PPT」可一次選取多份 .pptx，依封面的日期及次數建立歷史會議；已存在的次數只增加附件，保留既有紀錄。無法辨識封面或超過限制時，結果清單列出檔名與原因，請手動新增或處理未成功檔案。每場議題仍需點「整理成會議紀錄」確認。
- 勾選批次上傳的「僅保存文字與表格」可以不保留原檔，節省瀏覽器儲存空間；各頁解析文字與表格會納入一般備份。這種模式沒有圖片、原始版面或原檔下載，完整 PPT 請留在公司核准的資料夾。單一檔案上限 100 MB，完整 ZIP 備份上限 20 GB。
- 歷史議題可連結任何一場既有會議中的同一議題，包括時間較後面的第 219 次，讓補錄完成後的前次對照接得上。來源比對仍需人工確認，不以相似名稱直接合併。
- 左側會議列表獨立捲動，保留選取位置；手機版保留獨立橫向捲動列。欄位標籤 14px、主要輸入 15px（手機 16px），加深文字與提示顏色，版面結構維持原樣。

## 自動儲存與多分頁

每次編輯後短暫等待便自動存入 IndexedDB，右上角區分「儲存中」「已儲存」及「未儲存」。若另一分頁已更新同一工作區，較舊分頁不會覆蓋新版本；請先下載舊分頁需要保留的內容，再重新開啟最新紀錄。保存會議選取位置，編輯較早的會議後重新開啟也可接續。網站沒有帳號、雲端資料庫或跨裝置同步，GitHub Pages 公開的是網站程式，不是瀏覽器中的會議資料。

議題卡片列表可獨立垂直捲動，標題與搜尋欄留在列表上方。桌面列表隨編輯區停留於畫面側邊，選取議題及更新狀態時保留列表捲動位置；搜尋／篩選使用各自的位置，手機列表高度受限，不需滑過整份議題列表才到編輯區。

議題標題優先擷取原文中的文件、程序或工程議題名稱，剝離發文／提交的敘述前綴；例如 Topic 保留「軌旁安裝一致性測試程序」，文號、日期、版次與進度保留於簡報內容（Description）與來源原文。不確定的名稱仍保留原文摘錄供人工確認。現有紀錄可重新使用附件的「整理成會議紀錄」預覽並更新，既有討論與備註不會被清空。

PPT 原檔以獨立二進位檔儲存在 IndexedDB，不隨每次文字編輯重新寫入；舊版內嵌原檔會自動轉換。「儲存空間」顯示瀏覽器估計用量與配額，並可申請持續保存；是否核准由瀏覽器決定，這不會提高配額。頁面底部完整簡報文字面板已移除，議題內仍保留來源原文與原檔下載。

數 GB 歷史附件可依瀏覽器配額逐份匯入。完整備份使用 ZIP64（相容舊 ZIP 備份），以 Blob 組合原檔、逐段計算校驗碼；還原只讀取目錄、會議 JSON 與單份原檔片段，不再把整包備份載入 ArrayBuffer。完整備份單次上限 20 GB；單份 PPT 仍為 100 MB。這是程式上限，不代表瀏覽器保證提供 20 GB 空間。

議題名稱整理也適用於寫在 Topic 欄的進度敘述與非表格頁面；保留簡潔的明確標題，從敘述擷取文件／工程項目名稱。辨識範圍包含施工、測試、介面、作業行程等，中英文均依來源摘取，不翻譯或產生未提供的事實。不確定時仍保留原文摘錄供預覽修正；已建立的議題需重新整理附件並確認更新，不會自動改寫歷史紀錄。

依使用者確認的命名慣例：跨夜、每週配合施作時段歸為「夜班施工時間」；跨站工務軌旁作業行程保留站名清單；轉轍器所需更新數量去除請求對象與總站數。原文與簡報重點保留詳細限制，不推定缺少的英文翻譯。

「整理所有議題名稱 / Topic names」可對當次會議全部既有議題產生中英文名稱建議並一次套用，不需重新匯入簡報。預覽可編輯，保存後僅更新名稱；來源、討論、備註、負責人、狀態與跨週議題 ID 不變。單純重新整理網頁不會重寫已存名稱。命名規則涵蓋切換策略、軟體更新、平交道警報秒數、教育訓練意見與受損事件等工作主題；未能確定的名稱仍保留來源摘錄供修正。
