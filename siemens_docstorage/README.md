# 文件整理平台：直接上傳前端版

網址：`https://effylee1909.github.io/siemensintern/siemens_docstorage/`。

- 按「上傳文件」選取一份 PDF 或 DOCX，不需要指定／授權任何本機資料夾。選完後在瀏覽器解析、分類並保存在 IndexedDB；不傳至 GitHub 或外部辨識服務，不使用 Python 後端。
- 電子 PDF 直接擷取文字；掃描頁以本機繁中／英文 OCR 辨識。分類是規則建議，不是語意模型，須核對文號、客戶及引用。每份上限100MB、PDF150頁；OCR速度及準確率視裝置與檔案而定。
- 文件詳情可手動改分類／客戶／議題／版次，並確認公文引用。翻譯是既有Word，從「原檔與翻譯」補到對應公文，平台不翻譯。附件仍可複選。
- 同瀏覽器重新開啟會自動載入，不用每次重新上傳。無痕模式、清除網站資料、改用不同瀏覽器／裝置或配額不足可能失去資料。容量由瀏覽器與磁碟決定，**不保證一萬筆原檔或五萬份文件可全部容納**。用量估計是整個GitHub Pages同源網站共用，可能包含週會資料；不要為了此版清除同源網站資料。
- 可按「申請持續保存」，是否允許由瀏覽器決定。這不提高配額，也不能防止使用者清除資料。存檔失敗會明確提示，原檔與索引在同一交易寫入，避免只有索引卻沒有檔案。多分頁衝突拒絕覆寫。
- 「下載完整備份」建立未加密ZIP，包含原檔、辨識文字、分類、版本與引用關係。請放到公司核准的位置。換電腦可用「還原完整備份」，驗證全部內容後一次交易取代工作區；請先備份現有資料。單次備份讀取上限20GB、索引50MB，仍受裝置記憶體／瀏覽器配額限制。備份不是自動跨裝置同步。
- 示範資料不寫入真實工作區。按「返回我的文件」切回保存的資料。網站連結只分享工具，其他人不會看到你的文件。

## 之前版本

資料夾版的原檔／索引仍留在原來資料夾，不會自動搬入此版，也不會刪除；可逐份從原始PDF或DOCX重新上傳。目前不支援資料夾版索引JSON直接還原，因為那種索引沒有原檔。更早期瀏覽器原型保留在 `./legacy/`，可先匯出其備份；本次使用不同資料庫名稱，不覆寫舊版及週會資料。

## 驗證與建置

根目錄 `npm ci`、`npm test`、`npm run build:pages`。`scripts/docstorage-assets.mjs` 將OCR語言／WASM與PDF字型放到同網站，不需外部服務。瀏覽器測試 `npm run test:docstorage`，可用 `DOCSTORAGE_URL` 指向靜態測試站；測試以虛構PDF／掃描／DOCX驗證直接上傳、保存、完整備份跨瀏覽器還原、配額不足回復、手機版與無外部請求。測試檔位於`/tmp/docstorage-letter.pdf`、`/tmp/docstorage-scan.pdf`、`/tmp/docstorage-translation.docx`。

## 自動分類與人工核對

匯入完成後會回到總覽，在「分類」欄顯示自動結果；狀態分成「辨識中」「已自動分類・待核對」「未能自動分類」「辨識失敗」「已人工確認」。左側「待人工核對」包括已有分類、尚未確認的文件，不代表沒有執行分類；「未能自動分類」才表示沒有足夠分類依據。主旨欄位缺漏時會嘗試依內文關鍵詞提出分類，並說明依據；不會把所有未知文件硬歸為一般往來。

舊文件可開啟詳情按「重新辨識與分類」，使用已保存的原檔重跑，不必重新上傳。若已有手動欄位，會先詢問是否取代；已確認的引用關係會保留。掃描辨識錯誤或無法讀到文字時，請在「原檔與翻譯 → 讀取文字」核對，並查看失敗原因；沒有真實樣本時無法保證所有客戶格式都能正確分類。
