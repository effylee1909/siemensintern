# 文件整理平台：前端資料夾版

獨立網址：`https://effylee1909.github.io/siemensintern/siemens_docstorage/`。原週會網站路徑維持不變；Python 後端 Demo 另存於 `docstorage-platform/`，本版不使用它。

1. 使用電腦版 Chrome／Edge，在 HTTPS 網址開啟「開啟文件資料夾」，選擇專用空白資料夾並允許讀寫。關閉後重新進入需再次選取同一個資料夾。
2. 「批次匯入」接受 PDF／DOCX，每份最多100MB、PDF150頁、每批1000份。原檔複製至 `originals/`（UUID 檔名），頁面文字存至 `text/`，資訊存至 `siemens-docstorage-workspace.json`。原始來源檔不刪除。大量匯入前預留原檔副本與備份空間。
3. 電子 PDF 文字擷取、繁中／英文掃描 OCR、Word 文字讀取在瀏覽器內執行。OCR 程式／語言資源從同網站載入，文件內容不傳至 GitHub 或外部服務。初次載入 OCR 較大，須保持頁面開啟；部分掃描影像仍可能無法正確辨識。混合頁依可擷取文字量判斷，不保證涵蓋頁面所有影像文字。
4. 系統提供規則分類建議，非語意模型，尚無實際各客戶樣本準確率。可手動修改客戶、類別、議題、文號、期限原文並確認。已人工整理資料不會由後續附件辨識覆蓋。Word 翻譯是已翻譯好的文件，平台不翻譯。
5. 在文件「原檔與翻譯」補上翻譯 Word 或 PDF 附件，避免自動配錯公文。批次新匯入每檔建立一筆，不自動合併翻譯。引用文號須確認對應文件；同議題識別與已確認關聯可展開歷程，不把相鄰時間當成回覆證據。
6. 匯入可在目前文件完成後暫停；重新開啟同工作區按「續接未完成」。失敗項目可重試。仍在保存原檔時請勿關閉頁面。
7. 搜尋涵蓋文號、主旨、客戶、文件編號與檔名，**本版不提供全部PDF內容的全文搜尋**。辨識文字在選取單份文件後讀取，避免一次載入一萬份原檔。每頁30筆，已用10000筆合成索引測試搜尋／分頁；未驗證10000份真實文件的完整匯入、總OCR耗時或五萬筆規模。
8. 「下載索引備份」僅備份資訊與關聯，不包含原檔與辨識文字。**完整備份／換電腦請複製整個工作區資料夾**。索引還原僅接受同工作區ID；同資料夾避免多分頁修改，版本衝突會拒絕覆寫。
9. 舊版瀏覽器儲存資料保留，前往 `./legacy/` 可下載舊版完整備份；尚無舊版備份自動轉換。不要清除瀏覽器資料後才嘗試匯出。

分享網址只分享工具，其他人不會自動看到你的本機文件；本版沒有帳號或強制唯讀權限。它也不是公司的同步共享伺服器。

建置：根目錄 `npm ci`、`npm run build:pages`，同時產生週會、文件網站及舊版入口。OCR WASM／語言檔與 PDF 字型由 `scripts/docstorage-assets.mjs` 複製至文件網站子目錄。

測試：`npm test`；`scripts/docstorage-smoke.mjs` 針對正式輸出、以 OPFS 模擬資料夾選取測試真實瀏覽器檔案讀寫，並用虛構 PDF／掃描／DOCX 檔驗證。可用 `DOCSTORAGE_URL` 指定靜態測試站，測試用檔置於 `/tmp/docstorage-letter.pdf`、`/tmp/docstorage-scan.pdf`、`/tmp/docstorage-translation.docx`。這不取代實際作業系統的資料夾授權相容性驗證。
